## PART 3: Server pipeline (so I do not touch the backend)
1. **Webhook** `/webhook/meta`: GET verification uses the saved Verify Token (fallback env). POST: capture the exact raw body in server.ts (`express.json({ limit: '15mb', verify: (req, _res, buf) => { req.rawBody = buf } })`), verify `X-Hub-Signature-256` with HMAC-SHA256 over the raw bytes and the saved App Secret (timingSafeEqual; if no secret is saved, accept but warn once a minute), answer 200 immediately and process asynchronously. De-duplicate by Meta `mid` (Meta retries). Route each event to the owner userId through `mt_page_index` (objects `page` and `instagram`, by `entry.id`) or `mt_wa_index` (object `whatsapp_business_account`, by `metadata.phone_number_id`). Events for an unknown Page/number are ignored with a log line.
2. **Store** in Firestore: `users/{userId}/conversations/{channel}_{externalCustomerId}` (customerName, profilePic, channel, channelAccountId, lastMessage, lastMessageType, lastMessageSender, lastUpdated, unreadCount, botPausedUntil) and the subcollection `messages` (sender, text, attachmentUrl/mediaId, mid, status, timestamp). Handle: text, images/attachments, echoes (messages sent from the Facebook/Meta inbox, stored as mine), delivery and read receipts, WhatsApp status updates, ignore everything else without errors.
3. **Sending** `POST /api/inbox/send` (login required; body: conversationId, text and/or mediaId): look up the channel token of THAT conversation's owner, never a default user. Messenger and Instagram: `POST /me/messages` (messaging_type RESPONSE, recipient id = PSID/IGSID); WhatsApp: `POST /{phoneNumberId}/messages`. Never fake a success: save the message as sent only when Meta returns a `message_id`; on error return `{ success:false, error, code }` with a clear mapped reason (190 token invalid or expired, 200/10 missing permission, 100 invalid recipient, 551 cannot be reached, 24 hour window over, WhatsApp 131xxx errors) and show it in the chat as Failed + Retry. No "simulation sandbox" for real customers.
4. **Realtime without burning Firestore reads**: Server-Sent Events (`GET /api/inbox/stream`, login required) push new messages and status changes to the open browser. Keep the latest conversations and messages in a server memory cache, write-through to Firestore, and read Firestore only at start, when a conversation is opened for older messages, or after a restart. Fallback polling no faster than every 15 seconds and paused when the tab is hidden. Never read a whole collection in a poll or request handler. Load only the latest 30 conversations and 30 messages per opened chat.
5. **Security**: every `/api/inbox/*`, `/api/meta/*` (except webhook and data deletion) and settings route requires login; always filter by the userId from the login token, never from the request body or query. User A must never see or send as user B. The old routes that return tokens/secrets to the browser must return masked values only.
6. **Compliance**: `GET /privacy` (simple public Privacy Policy page) and `POST /api/meta/data-deletion` (verify `signed_request` with the App Secret, delete that user's stored conversations, return `{ url, confirmation_code }`).
7. `GET /api/health` (public, no secrets, no Firestore read): `{ ok, uptime, firestore: { ok, quotaExceeded }, channelsConnected }`.
